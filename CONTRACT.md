# DockMind API contract

Single source of truth between `/backend` and `/mobile`. Paths and field names follow the hackathon brief exactly. Anything marked **(added)** is our own extension and must not change the brief's fields.

Base URL: `http://<host>:8080` locally, where the Android emulator host is `10.0.2.2`, or `https://<name>.onrender.com` when hosted on Render. The app reads it from `EXPO_PUBLIC_API_URL`. JSON everywhere except the multipart upload and the A9 image. Single hard-coded clerk: `clerk-01`.

## API list

| # | Method | Path | Success | Purpose |
|---|---|---|---|---|
| A1 | GET | `/purchase-orders?status=OPEN` | 200 | List POs with lines |
| A2 | GET | `/receipts?status=` | 200 | List receipts, newest first, status optional |
| A3 | GET | `/receipts/{id}` | 200 | One receipt, polled after capture |
| A4 | POST | `/receipts` | 202 new, 200 replay | Upload photo, idempotent |
| A5 | PATCH | `/receipts/{id}/lines/{lineId}` | 200 | Clerk corrects a line |
| A6 | POST | `/receipts/{id}/confirm` | 200 | Confirm, safe to repeat |
| A7 | POST | `/receipts/{id}/dispute` | 200 | Dispute with reason, safe to repeat |
| A8 | PATCH | `/receipts/{id}` **(added)** | 200 | Clerk assigns the PO when it is unresolved |
| A9 | GET | `/receipts/{id}/image` **(added)** | 200 | Stored photo, the proof of delivery |

`GET /health` **(added)** returns `{ "status": "UP" }`, for the host's health check. It is not part of the app's API.

Swagger UI **(added)** is at `/swagger-ui.html`, and the generated OpenAPI document is at `/v3/api-docs`. This contract stays the source of truth for rules the generated docs cannot express.

## Lifecycle

`CAPTURED -> EXTRACTED | NEEDS_MANUAL -> CONFIRMED | DISPUTED`

- `EXTRACTED`: the note was read and the PO resolved.
- `NEEDS_MANUAL`: model failure, garbage output, an unreadable line, or PO unresolved. Never a 500, never a dropped receipt. `poNumber` is always null in this state and no line is linked.
- `CONFIRMED` and `DISPUTED` are terminal.
- A `NEEDS_MANUAL` receipt can be corrected (A5), assigned a PO (A8) or disputed (A7). It cannot be confirmed until a PO is assigned.

## Payloads

### A1 response

```json
[{ "id": "PO-4502", "poNumber": "PO-4502", "supplier": "Blue Ocean Seafood Co.", "status": "OPEN",
   "lines": [{ "id": "POL-4502-1", "sku": "SKU-SAL-10", "description": "Salmon fillet", "orderedQty": 80, "unit": "KG" }] }]
```

### A4 request

`multipart/form-data`, file field `image` (JPEG or PNG, max 10 MB, judged from the file's bytes rather than its declared type). Header `Idempotency-Key` is required, 1 to 255 characters, generated by the phone at capture time.

Optional header `X-Fixture: note-1|note-2|note-3|garbage` selects the fixture when `FixtureExtractor` is active. It is ignored by `LlmExtractor`. Without a valid header, the fixture comes from a `note-N` in the upload's file name, then from config `extractor.fixture.default`.

The response is the Receipt below. A new key returns 202 with status `CAPTURED` and `lines: []`. A repeated key returns 200 with the current state of the same receipt.

### Receipt (A2 array, A3, A4 to A8)

```json
{
  "id": "RCP-1042", "status": "EXTRACTED",
  "poNumber": "PO-4502", "supplier": "Blue Ocean Seafood Co.",
  "overallConfidence": 0.94,
  "aiNote": "Salmon is 8 kg short and scallops weren't ordered.",
  "lines": [
    { "id": "RL-1", "poLineId": "POL-4502-1", "description": "Salmon fillet",
      "orderedQty": 80, "receivedQty": 72, "unit": "KG",
      "confidence": 0.95, "discrepancy": "SHORT", "delta": -8,
      "aiQty": 72, "correctedByClerk": false, "needsReview": false }
  ],
  "deliveryNoteNo": "DN-30417", "poConfidence": 0.97, "freeText": null,
  "needsReview": false, "disputeReason": null, "clerk": "clerk-01",
  "createdAt": "2026-11-11T10:00:00Z", "updatedAt": "2026-11-11T10:00:09Z"
}
```

Fields from `aiQty` onward on a line, and from `deliveryNoteNo` onward on a receipt, are **(added)**. On a receipt, `poNumber`, `supplier`, `overallConfidence`, `aiNote`, `deliveryNoteNo`, `poConfidence`, `freeText` and `disputeReason` may be null. On a line, `poLineId`, `orderedQty`, `unit`, `confidence`, `delta` and `aiQty` may be null.

`aiNote` is written when the note is read and is not rewritten after a correction. If the note could not be read, it holds a plain instruction for the clerk.

`discrepancy`: `MATCH | SHORT | OVER | UNIT_MISMATCH | UNKNOWN_ITEM | NOT_DELIVERED`

### Requests

- A5: `{ "receivedQty": 70 }`, optional **(added)** `"unit": "KG"`. `receivedQty` runs from 0 to 1000000000. Recomputes `discrepancy` and `delta`, sets `correctedByClerk: true`, keeps `aiQty`. The clerk's number always wins.
- A6: no body. Repeating on a `CONFIRMED` receipt returns 200 unchanged.
- A7: `{ "reason": "..." }`, up to 2000 characters, blank reason returns 400. Repeating on a `DISPUTED` receipt returns 200 and keeps the first reason.
- A8: `{ "poNumber": "PO-4503" }`. Re-links lines by description, adds missing PO lines as `NOT_DELIVERED`, recomputes, moves the receipt to `EXTRACTED`. Sets `supplier` to the PO's supplier and `poConfidence` to 1.0, because the clerk has identified the PO. Repeating with the same PO returns 200 unchanged. A different PO on a receipt that already has one returns 409.

A8 links by normalized description (lower case, punctuation removed). It tries an exact match first, then a match where all the words of one description appear in the other, accepted only if exactly one PO line fits. So "Cheddar" links to "Cheddar, mature". Each PO line is linked at most once.

### Errors

`{ "error": "CODE", "message": "plain sentence" }`

| Status | When | `error` codes |
|---|---|---|
| 400 | Missing or invalid `Idempotency-Key`, missing image, file not JPEG or PNG, invalid body, blank or overlong reason, unknown `status` filter on A2 | `MISSING_HEADER`, `INVALID_IDEMPOTENCY_KEY`, `MISSING_IMAGE`, `INVALID_IMAGE`, `INVALID_QUANTITY`, `INVALID_UNIT`, `REASON_REQUIRED`, `REASON_TOO_LONG`, `PO_REQUIRED`, `INVALID_STATUS`, `BAD_REQUEST` |
| 404 | Unknown receipt, line, or PO. A line on a different receipt counts as unknown | `RECEIPT_NOT_FOUND`, `LINE_NOT_FOUND`, `PO_NOT_FOUND` |
| 409 | Confirm after dispute or dispute after confirm, editing a terminal receipt, deciding or assigning while `CAPTURED`, confirming with no resolved PO, assigning a different PO to a resolved receipt | `ALREADY_DISPUTED`, `ALREADY_CONFIRMED`, `RECEIPT_CLOSED`, `NOT_READY`, `PO_UNRESOLVED`, `PO_ALREADY_RESOLVED` |
| 413 | Image too large | `IMAGE_TOO_LARGE` |

## Matching rules (backend code only, never the model)

Units are normalized first (`KGS`, `kg` to `KG`; `CASES` to `CASE`; `EACH`, `PCS` to `EA`; `TRAYS` to `TRAY`). Rules apply in this order, per line:

1. No PO line linked: `UNKNOWN_ITEM`, `orderedQty` and `delta` null.
2. Linked, unit differs: `UNIT_MISMATCH`, `delta` null.
3. `receivedQty` equals 0: `NOT_DELIVERED`, `delta` is minus ordered.
4. Received below ordered: `SHORT`. Above: `OVER`. Equal: `MATCH`. `delta` is received minus ordered.

Every PO line absent from the note is added by code as `NOT_DELIVERED` with `receivedQty: 0`, `confidence: null`, `aiQty: null`.

`needsReview` (computed in code, threshold in config, default 0.80): a line is flagged when confidence is below threshold and the clerk has not corrected it. A receipt is flagged when any line is flagged, when `poConfidence` is below threshold, or when `poNumber` is null.

## PO resolution

A PO is resolved only if `poNumber` exists **and** the note's supplier agrees with that PO's supplier. PO-4503 and PO-4513 differ by one digit, so the number alone is not enough. If they disagree, `poNumber` is null, every line link is cleared, and the receipt goes to `NEEDS_MANUAL`. A `poLineId` that does not exist or belongs to another PO is cleared and that line becomes `UNKNOWN_ITEM`. If two lines claim the same PO line, the second link is cleared.

The supplier comparison ignores case, punctuation and company suffixes (`Ltd`, `Limited`, `Co`, `Company`, `Inc`, `LLC`, `PLC`, `Corp`). On a resolved receipt, `supplier` is the PO's supplier.

## Extractor output rules

Every extractor's answer goes through one validation layer before it is saved:

- Markdown fences and text around the JSON are removed. Numbers sent as strings are coerced, including `"1,072.5 kg"`.
- Confidence is clamped to 0..1, and `"95%"` reads as 0.95. A missing line or PO confidence counts as 0, so it is flagged.
- Unusable output, or a note with no lines, ends in `NEEDS_MANUAL` with `lines: []`.
- A line whose quantity is unreadable, negative or above 1000000000, or which has no description, sends the whole receipt to `NEEDS_MANUAL`. The line is kept with `receivedQty: 0`, `aiQty: null` and `confidence: 0`.

## Configuration

The server reads these from environment variables, or locally from the gitignored `backend/.env`. On Render they are set in the service's Environment tab.

| Variable | Default | Purpose |
|---|---|---|
| `EXTRACTOR_TYPE` | `fixture` | `fixture` returns the kit's canned answers, `llm` reads the photo with the model |
| `LLM_API_KEY` | none | Gemini key, needed for `llm` |
| `LLM_MODEL` | `gemini-2.5-flash` | Any vision-capable Gemini model |
| `PORT` | `8080` | Port to listen on, set by the host |
| `DOCKMIND_DATA` | `./data` | Folder for the H2 database |

## Working in this monorepo

Two agents run at the same time in the same working tree on branch `develop`.

- Backend agent writes only in `/backend` and `/kit`. Mobile agent writes only in `/mobile`.
- Neither agent edits `CONTRACT.md`. If it looks wrong, stop and report it.
- Stage and commit only your own folder: `git add backend kit` then `git commit -m "..." -- backend kit` (or `mobile`). Never use `git add -A`, `git stash`, `git reset`, `git checkout` of files, `git rebase`, or `git clean`.
- If git reports `index.lock`, wait a few seconds and retry. Do not delete the lock.
- Before each plan step, run `git log -8 --format="%h %s%n%b"` to see what the other agent has done.
- Commit after every plan step, with a real message.

### Commit format

Every commit lists the APIs it touches, using the numbers above. This is how the other agent tracks progress.

```
backend: add idempotent receipt capture

Why it changed, in one or two lines.

APIs:
- A4 POST /receipts [done]
- A3 GET /receipts/{id} [in progress]

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

Status tags: `[done]`, `[in progress]`, `[mocked]` (mobile against the mock), `[none]` (a commit that touches no API, written as `APIs: none`).
